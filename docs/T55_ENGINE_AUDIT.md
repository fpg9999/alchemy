### 3.5 任务 5：T35 优先级场景（PASS）

使用 8 个"自然反应新物质"作为不稳定物（由随机分子对的不完全反应产物中搜索得到，

#### 5c) 自分解后对新产品集合重判 —— 通过（重判语义）；完全解锁不可能

- **重判语义验证（6/6）**：对每个 U，令 `S2 = F(v_U) + B`，直接 `resolve(S2, T)` 的
  类型与产物，和"引擎先自分解再判定"的结果**完全一致**（且 S2 上 `stages=[]`）。
- **重判确实改变结果（6/6）**：若"跳过自分解、直接对原集合做不完全反应"，产物是原两分子复原
  （如 `[C2, XP2W3K2]`）；而实际引擎在自分解后对新集合判定，产物变为
  `[C2, PK, PK, XW3]` 等 —— 重判循环真实生效。
- **完全反应解锁：不可能（本模型内）**。`c(M) = Σ价数/2` 只由元素计数决定；
  `F(v_U)` 与原分子原子计数相同 ⇒ `Σc(F(v_U)) = c(U)`，自分解**不改变 Σc**，
  因此 resolve 第 1 步的判定（`T ≥ Σc` 与完整产物）在自分解前后完全不变。
  8/8 实测 `Σc(F(v_U)) == c(U)`。
  ⚠️ 这与 `docs/T35_PRIORITY_SELF_DECOMP.md` §3（示例 c(U)=5、F 产物总键数 3、T=9 时解锁完全反应）
  与 §6.3 的叙述矛盾 —— **文档层面问题，不是引擎 bug**（引擎按伪代码实现，结果自洽）。
- **不完全反应解锁实例：本样本未找到**。在 8 个不稳定物 × 3,931 个目录小分子中，
  未找到"分解前 T < Σi_old（原本不能不完全反应）、分解后发生不完全反应"的实例；
  其余重判效果已在上面 6/6 例中体现。

#### 5d) 多个不稳定同时满足：同轮全部自分解 —— 通过

`XP2W3K2 (c=10) + X2PW2KA (c=8)`，T=10（< Σc=18，且两个都满足 `T ≥ c_i`）：

产物 `[PK, PK, PK, X2W3A, XW2]` —— 同轮全部自分解，无顺序歧义。

- **几何**：引擎不检查几何可摆放（t28 的 `check_geometry` 未移植），若粒子环境要求产物合法摆放，
  需外接 `pot_v2.embed_mol2/validate_place`（风险点 4）。

## 4. T33 / T35 口径说明（重要）

- **T33 文档 = 旧 "max 阈值" 口径**：完全 `T ≥ max c(M)`；不完全 `T ≥ max i(M)`。
- **T35 文档 = 新 "全加和" 口径（当前实现）**：完全 `T ≥ Σc`；不完全 `T ≥ Σi`；
  自分解单分子 `T ≥ c(U)`，且自分解优先于不完全反应、完全反应优先于一切。
- `natural_engine.resolve` 与 T35 伪代码逐条对应：
  1. `T ≥ Σc` 且完全可行 → complete；
  2. 否则所有不稳定且 `T ≥ c(M)` 同时 `M → F(v_M)`，回到 1；
  3. 否则 `T ≥ Σi(含该键类的分子)` 且不完全可行 → incomplete；
  4. 否则 none。
- 用 W2A + WA3F2 验证：T=3 不完全（两口径同）；**T=5 旧 max=完全、新 sum=不完全**；
  **T=8 新 sum=完全**。另有 T=1 分歧（旧 max 不完全 / 新 sum 不反应）。
- **与 T35 文档的唯一实质偏差**：文档 §3/§6.3 的"自分解降低 Σc → 解锁完全反应"在本模型不成立
  （见 §5 风险点 2）；这是模型定义决定的，不是实现错误。

## 5. 疑点与建议（按重要度）

1. **【文档/模型口径】自分解不能降低 Σc，T35 的"完全反应解锁"叙述不成立。**
   `c(M)`（总键数）= 总价数/2，只由元素计数决定；`F(v_M)` 与原分子元素计数相同，
   所以 `Σc(F(v_M)) = c(M)`。自分解前后 resolve 第 1 步的 `T ≥ Σc` 与完整反应产物完全不变，
   "先分解、后被大锅一锅端"的连锁在本模型中不可能发生。
   本次审计 8/8 不稳定物实测 `Σc` 不变。
   **建议**：要么修正 T35 §3/§6.3 的文字与数值示例；要么若确实希望"自分解降低完全阈值"，
   需要把完全阈值改成不守恒的量（例如再引入能量/半衰期属性），不能用 c=总键数。
   （此项已写入 `t55_engine_audit.json` 的 `test5_t35.5c_rejudge`。）

2. **【固定键下的 level6 捕获 / 规则 10】属于设计风险，无独立理论基准。**
   `greedy_bond` 在"所有 d=6 候选耗尽"时捕获 level6 块，此时 `groups` 已包含
   `base_edges` 保留的骨架键，块可能跨过原分子的真实中间态边界；而 `pot_v4` 的 level6 定义
   只针对"从空键开始的完整反应"（HANDOFF §2.4 规则 10）。
   本次 420 对样本中规则 10/11 实际只改变 3 例结构、0 例分子式，未导致非法产物；
   但"带固定键时同块优先"的合理性没有像完整反应那样被全分支验证过。
   **建议**：若后续要提高置信度，用"三价 ≤11 全组合 + 随机断一根键"的固定键场景做一次
   与 pot_v4 同口径的 block 定义对照（或明确接受"当前连通块=中间态块"的近似）。

3. **【顺序/缓存依赖（低风险）】**。`incomplete_products` 与 `complete_products` 都按结构缓存；
   不完全反应的缓存键是"分子 label 多重集"，而结果理论上可能依赖输入顺序（并列取序）。
   420 对样本（其中 150 对显式做了正反序对比）未观测到差异，且缓存使同一结构集合在首次调用后固定，
   属可接受的一致性风险；若要求严格顺序无关，建议在 `incomplete_products` 内先按固定
   (formula,label) 排序再拼接原子。

4. **【引擎不做几何校验】**。`natural_engine.incomplete_products` 只做价数填满，不检查键型/几何
   可摆放（t28 的 `validate_products` 未移植）。粒子环境若需要"物理上可摆放"的产物，
   应在外部对产物调用 `pot_v2.embed_mol2 / validate_place`。

5. **【不稳定 = 同式不同构的情况】**。8 个不稳定物中 3 个（XCWK3、XW2KA2F、OX2P2W2KA）
   的 `F(v_M)` 分子式与 M 相同、只是结构不同。用**分子式**判断"是否分解/是否变化"会漏判；
   上层应按 `mol_label`/结构判断（引擎内部已如此）。

6. **【单分子自分解走 complete 分支】**。`resolve([不稳定 M], T≥c(M))` 返回 `type='complete'`
   而非 `stages` 里的 `self_decomp`（产物相同）。T35 伪代码本身"完全优先"，所以实现正确；
   但事件流/UI 需要知道这一点，避免把"自分解"统计成"大锅完全反应"。

7. **【孤立单原子/无定义 F 的对象】**。`is_stable` 对 F 无法定义的对象（如孤立 X 原子）返回 False
   （判为"不稳定"），但自分解产物为 None、`resolve` 会保留它并返回 none，不会死循环。
   正常分子对产物不会出现这种对象（价数填满），仅在手工构造输入时需注意。

## 6. 结论

- `natural_engine.py` 作为"规则 1~11 完全反应 + T28 v2 不完全反应（重结合升级为规则 1~11）+ T30 自分解 + T35 温度判定"的合并引擎，
  **实现与现有规则/文档口径一致，7 项审计全部通过，未发现功能性 bug**。
- 关键保证：完全反应与 `pot_v4` 逐字等价（14,444 向量 0 差异）；不完全反应与 `t28_rule_v2`
  仅差在规则 10/11 的预期结构差异（分子式 420/420 一致）；温度判定（完全优先、自分解优先、
  重判、同轮多分解、低阈值不反应）与 T35 伪代码一致。
- 需要在项目文档/玩法层修正的是：**T35「自分解降低 Σc → 解锁完全反应」的叙述与模型不符**（§5.1），
  以及"单分子自分解由完全反应分支承担"的语义（§5.6）。
- 风险提示：固定键下的 level6/规则 10 缺独立验证（§5.2）、无几何校验（§5.3）、
  输出顺序/缓存一致性（§5.4）——均不阻断当前使用，但建议在正式落地粒子环境前处理。
